# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Проект

«Книжная полка» — книжный блог на FastAPI с серверным рендерингом (Jinja2) и хранением в SQLite. Весь интерфейс, сообщения об ошибках, комментарии и docstring'и — на русском; новый код следует писать так же.

## Команды

Нужен Python 3.10+ (используется синтаксис `X | None`). Окружение — Windows/PowerShell.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py          # http://127.0.0.1:8000, uvicorn с reload=True
```

Эквивалент без `__main__`: `uvicorn main:app --reload`.

Тестов, линтера и сборки в проекте нет. Каталог не является git-репозиторием.

Чтобы вернуть начальные данные, удалите `books.db` — при следующем запуске он будет создан заново и заполнен из `SEED_BOOKS`.

## Архитектура

Модули с жёстким разделением: `main.py` — HTTP-слой (маршруты, разбор и проверка формы, шаблоны), `database.py` — всё, что касается SQLite, `auth.py` — хеширование паролей и токенов сессий (без SQL и без HTTP). ORM и Pydantic-моделей нет; SQL в `main.py` не пишется.

### Пользователи и сессии

- Таблицы `users` и `sessions`. Почта хранится в нижнем регистре и уникальна (`UNIQUE`): `create_user` и `update_user_email` при занятой почте возвращают `None` / `False`, а не бросают исключение.
- Пароль — PBKDF2-SHA256 с солью (`auth.hash_password`), минимальная длина задаётся `auth.MIN_PASSWORD_LENGTH`.
- Сессия — случайный токен в cookie `session`; в базе лежит только его SHA-256 и срок действия (`auth.SESSION_DAYS`).
- `main.get_current_user(request)` возвращает пользователя или `None`. Во всех шаблонах он доступен как `current_user` (контекст-процессор `user_context`).
- Читать книги может любой, а добавлять, править и удалять — только вошедший пользователь: эти маршруты без входа отвечают редиректом на `/login`. Владельца у книги нет — любой вошедший может менять любую.
- Каждая POST-форма вошедшего пользователя (книги, смена почты, выход) несёт скрытое поле `csrf_token`; оно доступно во всех шаблонах, а обработчик вызывает `main.check_csrf` (403 при несовпадении). Токен выводится из токена сессии (`auth.csrf_token`) и в базе не хранится. Новая форма без этого поля работать не будет.
- PBKDF2 считается долями секунды, поэтому в `async`-обработчиках `hash_password` и `verify_password` вызываются только через `run_in_threadpool`. `verify_password(password, None)` считает хеш впустую — так время ответа не выдаёт, есть ли такая почта.
- Попытки входа ограничены `auth.AttemptLimiter` (в памяти процесса): 5 за 15 минут на почту и 20 на IP, дальше — 429.

### Поток данных книги

- `database.FIELDS` — единственный источник списка редактируемых колонок. `create_book` и `update_book` собирают SQL из него и читают `data[f]` для каждого поля, поэтому словарь должен содержать **все** ключи из `FIELDS`.
- `main.parse_book_form` превращает форму в такой словарь и возвращает `(data, errors)`. Длины полей ограничены `main.MAX_LENGTHS`; те же числа продублированы в `maxlength` в `form.html`. Проверка — ручная, а не через Pydantic: при ошибках тот же `form.html` рендерится заново со статусом 422 и введёнными значениями, при успехе — редирект 303 на страницу книги (PRG).
- Добавление нового поля книги затрагивает сразу несколько мест: `SCHEMA`, `FIELDS` и `SEED_BOOKS` в `database.py`, `parse_book_form` в `main.py`, `templates/form.html` и шаблоны вывода. Миграций нет: `SCHEMA` — это `CREATE TABLE IF NOT EXISTS`, так что существующий `books.db` сам не изменится (нужен `ALTER TABLE` или пересоздание файла).

### База данных

- `get_connection()` — контекстный менеджер: новое соединение на каждый вызов, `commit` при успешном выходе, `row_factory = sqlite3.Row`. Шаблоны получают `sqlite3.Row`, а при повторном показе формы с ошибками — обычный `dict`; оба варианта работают в Jinja через `book.title`, но у `Row` нет метода `.get()` и он неизменяем.
- `init_db()` вызывается из `lifespan` при старте приложения и наполняет примерами только новую базу: признак «уже инициализирована» — `PRAGMA user_version = 1`. Если удалить все книги, после перезапуска полка останется пустой.
- Поиск в `list_books` намеренно выполняется в Python через `casefold()`, а не через SQL `LIKE`: в SQLite `LIKE` не учитывает регистр кириллицы. Поэтому и страницы (`main.PAGE_SIZE`) нарезаются в Python после фильтра; функция возвращает `(книги, всего)`.
- `list_books` выбирает только `LIST_COLUMNS` — без `content`, `created_at` и `updated_at`. Если карточке на главной нужно новое поле, его надо добавить и туда.
- `created_at`/`updated_at` хранятся как ISO-строки локального времени; сортировка списка — по `created_at DESC, id DESC`.

### Шаблоны

- `base.html` — каркас; `_macros.html` — общие макросы `cover` (обложка генерируется CSS-ом, оттенок `--hue` вычисляется из `book.id`) и `stars`.
- `form.html` обслуживает и создание, и редактирование; режим задаётся флагом `is_new`. Форма отправляется на тот же URL, с которого открыта.
- Фильтр `date` (регистрируется в `main.py`) форматирует ISO-дату по-русски: «10 октября 2026».
- Заметки (`content`) хранятся простым текстом; `book.html` делит их на абзацы по пустой строке (`\n\n`). `parse_book_form` для этого нормализует `\r\n` → `\n`.
- Все ошибки рендерятся через `error.html`: `HTTPException` (включая 404 для несуществующих маршрутов), ошибки параметров (404 — если ошибка в пути, 400 — если в строке запроса) и непредвиденные исключения (500).

### Маршруты

Порядок объявления важен: `/books/new` должен стоять выше `/books/{book_id}`. Удаление — `POST /books/{id}/delete` (HTML-формы не умеют `DELETE`).
